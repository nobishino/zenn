---
title: "第3章 型同士の関係と型方程式"
---

前章では、型推論を「型方程式を作り、その未知数にあたる型パラメータの型引数を求める処理」として眺めました。

この章では、型方程式が表している2種類の関係を確認します。

- `≡A`: 代入可能性にもとづく関係
- `≡C`: 型制約を満たすという関係

仕様書では、それぞれの `A` と `C` は下付き文字で書かれています。本書では読みやすさのため、`≡A`、`≡C` と書きます。

## 代入可能性から得られる関係

まずは前章と同じ例を使います。

<!-- zenncode: skip -->
```go
func G[T any](t T) {}

var x int
G(x)
```

関数呼び出し `G(x)` が有効であるためには、実引数 `x` を仮引数 `t` に渡せなければなりません。

- 実引数 `x` の型は `int`
- 仮引数 `t` の型は `T`

したがって、`int` と `T` の間には「実引数の型を仮引数の型へ代入できる」という関係が必要です。仕様書は、この関係から次の型方程式を作ります。

```text
T ≡A int
```

ここで `≡A` は、左右の型が代入可能性の規則に従って対応することを表します。

ただし、この式そのものを「`T` に `int` を代入できる」と読むのは適切ではありません。実際の関数呼び出しでは実引数から仮引数へという向きがありますが、仕様書は型推論を単純にするため、その向きを無視して対称な型方程式として扱うからです。

そのため、次の2つは型推論では同じ式です。

```text
T ≡A int
int ≡A T
```

英語で声に出して読むなら、`T matches int for assignability` や `T and int match under assignability rules` が意味を表しやすいでしょう。仕様書は記号の意味を説明していますが、公式な読み上げ方までは定めていません。

## 型制約から得られる関係

型パラメータ `T` には `any` という型制約があります。推論された型引数は、この型制約を満たさなければなりません。

この関係は次の型方程式で表されます。

```text
T ≡C any
```

仕様書は `X ≡C Y` を「`X` satisfies constraint `Y`」と説明しています。したがって、この式は「`T` は型制約 `any` を満たす」と読めます。英語でも `T satisfies constraint any` と読むのが自然です。

`≡C` には左右それぞれの役割があります。

- 左辺は、型引数を求めたい型パラメータ
- 右辺は、その型パラメータに対応する型制約

したがって `≡C` は対称ではありません。`T ≡C any` の左右を入れ替えた `any ≡C T` は、同じ意味の式にはなりません。

## 型方程式の両辺

`≡A` と `≡C` は、どちらも仕様書では型方程式と呼ばれます。しかし、両辺の役割は同じではありません。

| 記号 | 関係の出どころ | 左辺 | 右辺 | 対称か |
|---|---|---|---|---|
| `≡A` | 代入可能性 | 型 | 型 | 型推論では対称 |
| `≡C` | 型制約 | 型パラメータ | 対応する型制約 | 対称ではない |

`≡A` の両辺は型です。一方、`≡C` の右辺は型制約です。型制約はインターフェースによって表され、その型集合には `~[]E` のような制約でのみ使える型項が現れることもあります。そのため、`≡C` まで含めて「両辺には同じ意味で型が置かれる」と捉えるより、右辺には型制約が置かれると区別した方が分かりやすいでしょう。

また、ここでいう「方程式」は、数式の等号のように左右がまったく同じものだという意味ではありません。型推論が満たすべき型同士の関係を、`≡A` または `≡C` で表したものです。

## 2つの式をまとめる

`G(x)` から得られた関係をまとめると、次の2つになります。

```text
T ≡A int
T ≡C any
```

1つ目から型引数の候補 `int` が得られ、2つ目によってその候補が型制約 `any` を満たすことを確認できます。その結果、`T` の型引数として `int` を使えます。

```text
T ➞ int
```

この例では型パラメータが1つだけなので、関係は単純です。次章では仕様書の `dedup` の例を読み、複数の型パラメータを含む型方程式から、型引数が順に明らかになる様子を見ていきます。
